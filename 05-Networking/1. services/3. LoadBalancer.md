## Definition

**LoadBalancer** exposes the application to the internet by creating an **external cloud load balancer**. It automatically distributes incoming traffic to Pods.

> **Note:** This service type works on cloud providers such as AWS, Azure, and Google Cloud. In local clusters like Minikube or Kind, an external IP is not created unless additional tools (for example, MetalLB) are installed.
### Features

- Publicly accessible.
- Automatically creates:
    - ClusterIP
    - External Load Balancer
- High availability.
- Distributes traffic among Pods.
### Use Cases

- Production applications
- Public APIs
- Websites
- Enterprise applications
## Architecture

```bash
Internet
      |
 Load Balancer
      |
 Kubernetes Service
      |
     Pods
```
### Create using kubectl

```bash
kubectl expose deployment nginx \
  --type=LoadBalancer \
  --port=80 \
  --target-port=80
```
### Yaml:
```bash
apiVersion: v1
kind: Service
metadata:
  name: loadbalancer-svc
spec:
  type: LoadBalancer
  selector:
    app: nginx
  ports:
  - port: 80
    targetPort: 80
```

Command:
```bash
# Apply
kubectl apply -f loadbalancer.yaml

# Verify
kubectl get svc
```
#### Start the Minikube Tunnel
```bash
minikube tunnel
```
Keep this command running. It assigns an external IP to the LoadBalancer service.
#### Check again serivces
```bash
kubectl get svc

# Example:
NAME    TYPE           CLUSTER-IP      EXTERNAL-IP   PORT(S)
nginx   LoadBalancer   10.96.120.100   10.96.120.100 80:30992/TCP
```
#### Access the Application
```bash
http://<EXTERNAL-IP>
```

### Quick alternative in Minikube
```bash
minikube service nginx
```
