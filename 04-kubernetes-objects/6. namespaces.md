A **Namespace** is a way to **logically separate and organize Kubernetes resources** inside the same cluster.

Think of it like **different departments in a company**:
```shell
Kubernetes Cluster
│
├── development
│   ├── Pods
│   ├── Services
│   └── Deployments
│
├── testing
│   ├── Pods
│   └── Services
│
└── production
    ├── Pods
    ├── Services
    └── Deployments
```
The same Kubernetes cluster can have multiple environments using different namespaces.
### Why use Namespaces?

- **Organize** resources
- Separate **development / testing / production**
- Apply **RBAC permissions** per namespace
- Apply **resource limits** per namespace
- Avoid naming conflicts

### Creating a Namespace in YAML
```shell
apiVersion: v1
kind: Namespace
metadata:
  name: development
  labels:
    name: development
```

Using kubectl command:
```shell
kubectl create namespace development
```

Important Command:
```shell
# List namespace
kubectl get ns 

# Create a Pod inside a namespace
kubectl run nginx --image=nginx -n development

# Get Resources from all namespaces
kubectl get pods --all-namespaces
kubectl get all 
kubectl get all -n development    # with specific namespace

# Delete the namespace
kubectl delete ns development

# Set other specific namespace as a default  
kubectl config set-context --current --namespace=development
```
