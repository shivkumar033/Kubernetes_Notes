## Definition

**LoadBalancer** exposes the application to the internet by creating an **external cloud load balancer**. 
and it normally use your application using domain name like (example.com).
It automatically distributes incoming traffic to Pods.
### Features

- Publicly accessible.
- Automatically creates:
    - ClusterIP
    - External Load Balancer
- High availability.
- Distributes traffic among Pods.
### Use Cases

- Production applications
- Public APIs
- Websites
- Enterprise applications
## Architecture

```bash
Internet
      |
 Load Balancer
      |
 Kubernetes LB Service
      |
     Pods
```
### Create using kubectl

```bash
kubectl expose deployment nginx \
  --type=LoadBalancer \
  --port=80 \
  --target-port=80
```
### Yaml:
```bash
apiVersion: v1
kind: Service
metadata:
  name: loadbalancer-svc
spec:
  type: LoadBalancer
  selector:
    app: nginx
  ports:
  - port: 80
    targetPort: 80
```

Command:
```bash
# Apply
kubectl apply -f loadbalancer.yaml

# Verify
kubectl get svc
```
#### Start the Minikube Tunnel
```bash
# 1. options
minikube tunnel

# 2. options
minikube service nginx --url
```
Keep this command running. It assigns an external IP to the LoadBalancer service.
#### Check again serivces
```bash
kubectl get svc

# Example:
NAME    TYPE           CLUSTER-IP      EXTERNAL-IP   PORT(S)
nginx   LoadBalancer   10.96.120.100   10.96.120.100 80:30992/TCP
```
#### Access the Application
```bash
http://<EXTERNAL-IP> 
```

### Access Your application using the domain name
```bash
# You can create a **local domain** such as:
myapp.local

# On Windows, edit:
C:\Windows\System32\drivers\etc\hosts

# ADD
EXTERNAL-IP    myapp.local

# Now open Browser and search it:
http://myapp.local
```
